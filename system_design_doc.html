4.6 High level architecture of the developed system

The ED-RMS system architecture is designed to support a robust, secure, and scalable matching process. It follows a standard three-tier architecture model, separating the presentation layer from the business logic and data storage.

%%{init: {'theme': 'default', 'themeVariables': { 'fontSize': '15px'}}}%%
flowchart TD
    subgraph Client ["Client Layer"]
        Browser("Web Browser (React/Vite)")
    end

    subgraph Logic ["Application Logic Layer"]
        API("Laravel REST API Engine")
        Matching("MCDA Matching Engine")
    end

    subgraph Data ["Data Layer"]
        DB[("MySQL Database")]
    end

    Browser <-->|JSON over HTTPS| API
    API <-->|Internal Call| Matching
    API <-->|SQL Queries| DB

    classDef layer fill:#f1f8ff,stroke:#2c5f9e,stroke-width:2px;

Figure 1: High-Level System Architecture

Architectural Components

Tier Technology Responsibility
Presentation Layer React.js (Vite) Provides user interfaces for Donors, Recipients, Clinicians, and Admins. Handles client-side validation and rendering.
Application Logic Layer PHP (Laravel 11) Processes logic, authenticates requests (Sanctum), enforces RBAC, and executes the sophisticated Multi-Criteria Decision Analysis (MCDA) matching engine.
Data Management Layer MySQL (XAMPP) Stores structured relational data including profiles, consent documents, and matching audit logs.

4.7 The Flow Chart of the developed system

The Flow Chart visually represents the step-by-step sequence of operations and decisions that occur within the ED-RMS system, from user registration through to the final matching process and clinician review.

%%{init: {'theme': 'default', 'themeVariables': { 'fontSize': '15px'}, 'flowchart': { 'nodeSpacing': 50, 'rankSpacing': 60}}}%%
flowchart TD
    Start([Start]) --> Login{User Registered?}
    Login -- No --> Register[Register User Account]
    Register --> Role{User Role?}
    Login -- Yes --> Auth[Authenticate]
    Auth --> Role
    
    Role -- Donor --> DonorDash[Access Donor Dashboard]
    DonorDash --> MedProf[Submit Medical Profile and Consent]
    MedProf --> PendingApproval[Await Clinician Approval]
    
    Role -- Recipient --> RecipDash[Access Recipient Dashboard]
    RecipDash --> SetPrefs[Submit Preferences and Diagnosis]
    SetPrefs --> ReqMatch[Request Match]
    
    Role -- Clinician --> ClinDash[Access Clinician Dashboard]
    PendingApproval -.-> ClinDash
    ReqMatch -.-> ClinDash
    
    ClinDash --> Trigger[Execute Matching Engine]
    Trigger --> MCDA[Apply Hard Filters and MCDA Algorithm]
    MCDA --> Results[Generate Ranked Matches]
    Results --> Review{Clinician Review}
    
    Review -- Approved --> Notify[Notify Recipient and Donor]
    Review -- Rejected --> Discard[Discard Match]
    
    Notify --> End([End Process])
    Discard --> End
